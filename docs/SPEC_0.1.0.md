# Isora 0.1.0 — техническое задание

Статус: в разработке. Текущая версия хранится в `VERSION.txt`.

## Цель

Сделать Isora надёжным локальным менеджером QEMU/KVM-машин для Arch Linux с установкой только из нативного pacman-пакета. Windows backend сохраняется в проекте, но не входит в текущий релизный контур.

## Релизный артефакт

- `isora-<pkgver>-1-x86_64.pkg.tar.zst`;
- установка и обновление только через `sudo pacman -U`;
- сборка только локально на Arch Linux;
- в GitHub Release вручную загружается только pacman-пакет;
- одновременно существует только один Release, прежние Releases и связанные теги удаляются перед публикацией нового;
- GitHub Actions и другие удалённые сборщики не используются.

GitHub автоматически добавляет к Release ссылки на архивы исходников. Они не являются загруженными артефактами и не отключаются настройками репозитория.

## Linux backend

- подключение к `qemu:///system`;
- storage pool `isora` в `/var/lib/libvirt/images/isora`;
- QEMU/KVM, libvirt, SPICE/virt-viewer и опциональный OVMF;
- отдельные QCOW2-диски машин;
- импорт ISO с SHA-256;
- snapshots, резервные копии и проверка восстановления;
- запрет неявного доступа к физическим и сетевым дискам.

## Windows backend

Код прямого QEMU/WHPX backend сохраняется. Он использует QMP, отдельный реестр машин и SDL-окно гостя. Arch-релизный скрипт не собирает и не публикует Windows-артефакты.

## Локальное меню

`./isora.sh` предоставляет цифровые пункты для:

1. сборки pacman-пакета из текущих исходников;
2. публикации единственного актуального GitHub Release;
3. установки собранного пакета;
4. commit + push всех изменений с сообщением пользователя;
5. `pull --rebase` изменений других участников;
6. просмотра состояния проекта.

Публикация разрешена только из чистой и полностью отправленной ветки `main`. Версия пакета должна совпадать с `VERSION.txt`.

## Проверка Arch-релиза

1. Собрать пакет пунктом 1.
2. Проверить метаданные пакета через `pacman -Qp`.
3. Проверить наличие `usr/bin/isora`, `usr/bin/isoractl` и desktop entry внутри архива.
4. Установить пакет пунктом 3, фактически использующим `sudo pacman -U`.
5. Проверить запуск GUI, CLI, libvirt, создание VM и lifecycle.
6. Опубликовать пунктом 2 и проверить, что на GitHub остался один Release с одним загруженным пакетом.
